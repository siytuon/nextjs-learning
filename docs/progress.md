### 今後確認する理解ポイント

1. `app/page.tsx` の `Home` は画面を返すReactコンポーネント。Javaのメソッドに似ているが、戻り値はHTMLに似たJSXになる。
2. `players.map(...)` は、選手の配列を1行ずつの表示へ変換する。SQLの検索結果を行ごとに画面部品へ写す感覚に近い。
3. 実データは `data/players-2026.csv` に保存し、`lib/players.ts` が文字列を数値へ変換して画面へ渡している。DBやAPIから取得した値をDTOへ詰め替える処理に近い。

## 第4回の予定: 選択状態の同期と選手比較

### 次回30分の進め方

1. `./scripts/npm22 run dev`で起動し、現在の選手選択と詳細表示を確認する
2. `selectedPlayer`が`PlayerTable`内にあるため、サマリーから利用できないことをコードで確認する
3. サマリーとテーブルを包むClient Componentを作り、`selectedPlayer`をそこへ移す
4. `PlayerTable`へ`selectedPlayer`と`onSelectPlayer`をpropsで渡す
5. サマリーの選手名をクリック可能にし、同じ`onSelectPlayer`を呼び出す
6. サマリー・テーブル・詳細を閉じる操作で、選択状態と色が同期することを確認する

### 理解するポイント

- stateは、その値を必要とするコンポーネントに共通する最も近い親へ置く
- 子はstateを直接変更せず、親から受け取ったコールバックで変更を依頼する
- Server Componentの`page.tsx`では`useState`を使えないため、対話部分を担うClient Componentが必要になる
- 同じ選手かどうかを、画面上の色ではなくデータの一意な値で判定する
